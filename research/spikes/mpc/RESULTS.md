## 6. Spike B — contract-initiated (`contract/src/lib.rs`, `js/sign_contract.mjs`)

### 6.2 All other Spike B runs

The full table is in `data/spikeB_table.md` (generated from `data/spikeB.jsonl`). Highlights:

- **Concurrency.** 3 concurrent (`B-conc-3b`: `CoRMrypq…`, `2gbHxRrN…`, `8TiEpEFM…`) all OK in 5.9–6.8 s. 10 concurrent (`B-conc-10`) all OK in 5.4–7.9 s, from one sender with nonces N+1…N+10 in flight together. The fix was to serialize submissions.

### 6.5 Other checks

- **FC access key cannot attach the 1 yocto** (`js/fc_key_test.mjs`, `fc_key_test2.mjs`). A temporary FC key (receiver = spike, allowance 0.25 NEAR) was added (`HVUJmwk5ByDbA3Ln14utHupRm4X7rH4QSqFZDxsdsAXU`) and deleted (`2y4PKWLze1YujZp6ZAdd1tjphVKKZCT25BQNeVKvHHyt`). With 1 yocto, `send_tx(wait_until=INCLUDED)` returned `{"TxExecutionError":{"InvalidTxError":{"InvalidAccessKeyError":"DepositWithFunctionCall"}}}`; with `wait_until=NONE` the tx is silently dropped. With 0 yocto, `sign_for` panicked `ERR_ATTACH_1_YOCTO` (`7UvoAwYjhDKENCc8v41depyeydkeNutN3yXQzWXLc3e6`).
- **Blocking RPC** (`js/blocking_send.mjs`, fastnear). `send_tx(wait_until=EXECUTED_OPTIMISTIC)` returned the signature in 7.3 s; `FINAL` in 13.0 s. On the timeout path (spike2 → mock) the blocking call returned after **30.1 s** with `{"name":"HANDLER_ERROR","cause":{"info":{"cause":"PENDING","status":{"final_execution_status":"INCLUDED_FINAL",…` (partial status), so the client must keep polling.
- **Gas price / hold.** `gas_price` RPC = 1e8 yocto/gas; `min_gas_purchase_price` = 1e9. Refund receipts for a 100 Tgas attach totalled 0.0997 NEAR, meaning the signer must hold about **0.1 NEAR per 100 Tgas attached** until refunds land (a few blocks). Only ~0.0012 NEAR is actually burnt.

## 7. Environment gotchas hit during the spike

1. **near-sdk 5.29.1 doesn't build on rustc 1.93 by default.** It depends on `near-sdk-env = "~0.1.6"`, which resolves to **0.1.7 (published 2026-10-19, `rust_version = 1.95`)**. cargo-near fails with `rustc 1.93.0 is not supported by the following package: near-sdk-env@0.1.7 requires rustc 1.95`. Fix: `cargo update near-sdk-env --precise 0.1.6` and commit Cargo.lock.
2. **RPC.** `rpc.testnet.near.org` now answers `{"code":-429,"message":"WARNING! THIS ENDPOINT IS DEPRECATED! STOP USING IT NOW! Switch to https://fastnear.com …"}`. `rpc.testnet.fastnear.com` / `test.rpc.fastnear.com` / `archival-rpc.testnet.fastnear.com` rate-limit under team load (HTTP 429 and/or JSON-RPC `code -429 "Rate limits exceeded"`). The near CLI hit it too: `this client has exceeded the rate limit`. `https://near-testnet.drpc.org` worked as a fallback (it returns 403 to Python's default urllib User-Agent).
3. **Finality lag.** Right after `EXECUTED_OPTIMISTIC`, `view_*` with `finality: final` can still show the old state (`UNKNOWN_ACCESS_KEY`, `CodeDoesNotExist`) for 1–3 s.
4. zsh: a loop variable named `path` clobbers `$PATH` (exit 127).
5. The near CLI auto-migrated its config (`Migrating config.toml from V4 to V5…`) on one call. The testnet `rpc_url` stayed `https://archival-rpc.testnet.fastnear.com/`.
